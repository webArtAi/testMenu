# Дружба — сайт меню из Excel

## Инструкция для пользователя

Меню меняется в **menu.xlsx**, на листе **Меню**. Программу-редактор устанавливать не нужно. После загрузки Excel и новых фото в GitHub сайт автоматически собирается и обновляется.

- **Первая строка блюда**: раздел, название, порция, цена, описание, фото, «Да/Нет», постоянный код.
- **Строки сразу под ним с пустым названием**: дополнительные порции этого же блюда. В них заполняйте только C (порция) и D (цена).
- **Цена** — число без ₽. Формулы не используются.
- **Фото** — только имя файла из `photos`, например `omelet.webp`. Без ссылки Google Drive и без `photos/` в начале. Пустое поле — заглушка.
- **Показывать**: Да / Нет. Выключается вся карточка со всеми порциями.
- **Код** существующего блюда не меняйте. Для нового блюда оставляйте его пустым.
- **Бонус к блюду** — колонка I. Указывайте его в первой строке нужного блюда; пустое поле означает отсутствие бонуса.
- Не сортируйте отдельные строки: варианты должны оставаться под своим блюдом. Для поиска используйте Ctrl+F.

Остальные листы: **Разделы** — список разделов; **Настройки** — название/контакты/тексты/режим макета; **Ссылки** — настоящие HTTPS-ссылки кафе; **Как пользоваться** — краткая справка.

## Первая настройка GitHub Pages

1. Создайте отдельный репозиторий. Для бесплатного личного GitHub Pages он обычно должен быть публичным. Поставьте галочку создания README, чтобы появилась ветка main.
2. В репозитории откройте **Settings → Pages**. В **Build and deployment → Source** выберите **GitHub Actions**. Это важно: не «Deploy from a branch» из прежней схемы.
3. Убедитесь, что работа идёт в ветке **main**. Если имя другое, прежде согласуйте настройку workflow.
4. Загрузите содержимое подготовленных папок «Загрузка-01», затем «Загрузка-02» через **Add file → Upload files**. Не загружайте сами папки «Загрузка-01/02». На каждом шаге подтвердите **Commit changes**. В последней порции есть `.github/workflows/pages.yml` — она запускает сборку после загрузки всех исходников.
5. Во вкладке **Actions** откройте «Обновить меню на сайте». Дождитесь зелёных отметок у сборки и публикации.
6. Откройте **Settings → Pages** и используйте адрес сайта, который покажет GitHub. Либо нажмите ссылку у результата задания публикации.
7. Если сайт ещё не готов, дождитесь завершения запуска. Не обещаем фиксированное время обновления.

В репозиторий загружаются исходники проекта: Excel, `photos`, `assets`, `templates`, `build.py`, `requirements.txt`, `tests` и `.github`. Папку готового просмотра и внутренние памятки туда не загружайте. Полная пошаговая инструкция лежит снаружи репозитория в общем комплекте.

## Обычное обновление

1. Измените Excel и сохраните как `menu.xlsx`.
2. Если добавили новое фото — сначала загрузите его **в папку photos** на GitHub.
3. Затем загрузите обновлённый **menu.xlsx в корень репозитория**, заменив прежний.
4. Проверьте последнюю сборку во вкладке Actions, затем страницу сайта.

При загрузке фото отдельно может пройти сборка со старой таблицей — это нормально. Последняя сборка после загрузки Excel использует новые данные. Если сборка падает, прежняя успешно опубликованная версия остаётся доступна, новая не публикуется.

## Для разработчика

Python 3.12, openpyxl, Pillow; статические HTML/CSS/JS. Нет Electron, Node.js на стороне пользователя, CMS, БД или CDN. Сайт формируется с готовым HTML из `templates/index.html`. Относительные пути работают в GitHub project pages и локально.

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python build.py
```

Результат — `site/`. Исходный Excel и `photos/` не перезаписываются. При ошибке валидации или фото прежняя локальная сборка не заменяется. Сборка в GitHub Pages использует официальный служебный доступ Actions; вручную выдавать персональный токен не нужно.

Исходные 600 МБ фотографий остаются у владельца/на Диске. В `photos` — подготовленные WebP для сайта. Новый JPEG/PNG/WebP можно добавить в эту папку; сборщик создаст размеры 720/1200 с учётом EXIF и без увеличения.

## Текущий статус

Начальный набор: 14 разделов, 112 карточек, 129 порций/цен, 110 карточек с фото. Для чая и лимона пока заглушки. Чай — одна карточка с полным списком вариантов внутри; внешнюю цену «от 40» не выбираем без окончательного решения. Соусы и кутабы — отдельные карточки. Два временных назначения фото зафиксированы в отдельной памятке для пользователя.

По умолчанию в Excel включена **Предварительная версия: Да** — выставлен noindex. Верхняя надпись о проверке убрана по просьбе пользователя. Это не пароль и не защита доступа: опубликованный сайт всё равно можно открыть по ссылке. После проверки пользователем можно выбрать Нет, подтвердить данные и указать настоящий «Сайт URL» для sitemap/canonical.

Локальная сборка и тесты выполнены. Публикация и обновления через GitHub Actions проверены пользователем. Визуальное тестирование в Cloud-браузере недоступно (нет предусмотренного инструмента), DOM-тесты его не заменяют. Инструкцию можно дополнить скриншотами из используемого аккаунта.

## Изменения версии 1.1

Удалена верхняя надпись о проверке; настройка поисковой индексации действует независимо от оформления. Логотип заменён на центральную плашку с прозрачным окружением. Телефон и Telegram видны в закреплённой шапке, в том числе на мобильном экране. Пока ссылка не передана, Telegram показан с подписью «скоро» и не открывает фиктивный адрес.

Ссылку вставлять на листе «Настройки» в строке **Telegram URL**. Если в прежнем Excel этой строки нет, можно добавить её в конец: A — Telegram URL, B — реальный адрес https://t.me/.... Альтернативно поддерживается строка с подписью Telegram на листе «Ссылки». Телефон берётся из существующей настройки «Телефон».

Окно «Разделы» содержит категории, переходы «О кафе» / «Адрес и контакты», телефон и Telegram. Дополнительные плавающие кнопки и WhatsApp пока не добавлены: способы связи доступны в шапке, номер/ссылка WhatsApp не подтверждены.

Индивидуальное приближение фотографий в карточках хранится в `photo-framing.json`. Сохраняйте этот файл вместе с проектом; пользователю не требуется редактировать его вручную. В подробностях блюда фотография показывается целиком.
